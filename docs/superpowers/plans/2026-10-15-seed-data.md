# Seed Data Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mengisi Supabase dengan katalog, materi, dan bank soal Dasar Pemrograman yang terverifikasi, secara idempoten, tanpa mengubah skema tim kecuali satu policy yang disetujui.

**Tech Stack:** JSON, Node ESM (tanpa dependensi baru), Vitest, Python 3.12 (verifikasi kode), Supabase CLI.

**Spec:** `session-progress.md` bagian "Konten & alur belajar (2026-10-15)" + jawaban DB 2026-10-15 (hanya policy `student_mastery` wajib; sisanya dipetakan di generator) + migrasi aktual `supabase/migrations/20261013035717_fullSql.sql` (dibaca penuh untuk plan ini — lihat "Koreksi terhadap migrasi" di bawah).

## Koreksi terhadap migrasi

Rancangan di atas ditulis sebelum migrasi dibaca baris per baris. Berikut semua titik di mana desain awal tidak cocok dengan `20261013035717_fullSql.sql`, dan perbaikannya. Setiap keputusan desain di bawah bagian ini sudah memasukkan koreksi ini; daftar ini hanya mencatat *apa yang berubah dan mengapa*.

1. **`topics.subject` adalah `TEXT NOT NULL` tanpa default**, dan `TopicContent` di `src/content/types.ts` **tidak punya field `subject`** sama sekali (field yang ada: `slug`, `name`, `language`, `level`, `description`, `units`). Rancangan awal diam-diam mengandalkan konten untuk mengisi semua kolom topik, padahal kolom ini tidak ada sumbernya di JSON. **Perbaikan:** `subject` diisi dari peta `CATEGORY_SUBJECT` di `mappings.mjs` berdasarkan kategori topik (untuk "Dasar Pemrograman" di bawah kategori "Pemrograman" → `subject = "Pemrograman"`), **bukan** dari file konten. Ini sengaja menghindari menambah field baru ke `TopicContent` (constraint "tidak mengubah skema tim" tidak berlaku ke sini, tapi tetap menghindari perubahan skema konten yang tidak perlu). Dicatat sebagai asumsi terbuka — lihat "Terbuka" #5.
2. **`topics` punya constraint unik ganda**: `slug TEXT NOT NULL UNIQUE` **dan** `UNIQUE (name, subject)`. Rancangan awal hanya menyebut `on conflict (slug)`. **Perbaikan:** upsert tetap `on conflict (slug) do update ...` (aman untuk re-run topik yang sama), tapi T4 menambah tes yang menjamin generator tidak pernah menghasilkan dua topik dengan `(name, subject)` sama — relevan begitu topik kedua ditambahkan di masa depan, bukan masalah sekarang karena hanya 1 topik.
3. **Tidak ada kolom `source` di `quiz_questions` sama sekali.** Rancangan awal (mengikuti catatan usang di `02-database-schema.md`/`session-progress.md` tentang "`questions.source` manual/ai") salah menerka lokasi kolom ini. Kolom yang benar-benar ada adalah **`topics.source_type TEXT NOT NULL DEFAULT 'admin' CHECK (source_type IN ('admin', 'ai'))`** — bukan `'manual'`/`'ai'`, dan letaknya di `topics`, bukan di `quiz_questions`. **Perbaikan:** generator mengisi `topics.source_type = 'admin'` (karena topik ini dikurasi tim, bukan dibuat AI saat runtime); referensi ke "kolom `source` pada `quiz_questions`" dihapus dari rencana. Asal-usul tiap soal ("AI membuat draf, model utama meninjau") tetap didokumentasikan di `docs/content-style-guide.md`, bukan di kolom DB.
4. **Default `is_published` berbeda-beda per tabel dan berlawanan arah**: `categories` default `TRUE`, tetapi `topics`, `materials`, dan `quiz_questions` semuanya default **`FALSE`**. Rancangan awal menyebut "is_published=true" di teks naratif tapi tidak menegaskan bahwa ini **wajib ditulis eksplisit** di setiap `INSERT`/`UPDATE` — mengandalkan default akan membuat topik/materi/soal tidak pernah terlihat siswa. **Perbaikan:** `renderSql.mjs` selalu menulis `is_published` secara eksplisit (true untuk baris aktif, false untuk cabang unpublish) pada ketiga tabel ini; T5 menambah tes yang menegaskan tidak ada baris INSERT yang mengandalkan default `is_published`.
5. **`materials.content` bertipe `TEXT`, bukan `JSONB`.** Keputusan `JSON.stringify(material)` dari rancangan awal tetap benar (string JSON disimpan sebagai teks biasa), tapi `renderSql.mjs` tidak boleh melakukan cast `::jsonb` ke kolom ini — hanya `sqlString()` biasa. Ditegaskan di T2/T5 agar tidak ada yang mencoba `'...'::jsonb` ke `materials.content`.
6. **Constraint tabel `quiz_questions`: `CHECK (material_id IS NOT NULL OR step_id IS NOT NULL)`.** Desain "satu `materials` per skill, soal menunjuk `material_id`, `step_id = null`" sudah otomatis memenuhi ini (karena `material_id` selalu diisi), tapi ini sebelumnya tidak diverifikasi terhadap teks migrasi — sekarang dikonfirmasi aman, dan T4 menambah tes eksplisit (`step_id` selalu `null`, `material_id` selalu UUID valid) supaya regresi di generator tidak diam-diam melanggar constraint ini.
7. **`quiz_attempts.question_id REFERENCES quiz_questions(id) ON DELETE CASCADE`** dikonfirmasi ada di migrasi — ini membuktikan (bukan hanya menduga) alasan keputusan #6 "jangan DELETE, cukup `is_published = false`": menghapus baris `quiz_questions` akan ikut menghapus riwayat jawaban siswa (`quiz_attempts`) lewat cascade. Tidak ada perubahan rencana, hanya dicatat sebagai bukti yang memperkuat keputusan yang sudah ada.
8. **Tidak ada policy RLS `INSERT`/`UPDATE` apa pun untuk `categories`, `topics`, `materials`, atau `quiz_questions`** — hanya `SELECT ... USING (is_published = true)`. Ini berarti seed **tidak bisa** dijalankan oleh peran `anon`/`authenticated` sama sekali (bukan hanya "butuh izin tim" seperti disebut rancangan awal secara longgar) — harus lewat koneksi yang bypass RLS: `postgres`/`service_role` (yang dipakai otomatis oleh `supabase db reset` secara lokal), atau `psql`/SQL editor dengan kredensial admin di hosted. Ditegaskan di T7/T15.
9. **`materials.estimated_minutes` punya `CHECK (estimated_minutes > 0)`.** Default 8 dari rancangan awal valid, tapi `mappings.mjs` perlu `Math.max(1, Math.round(value))` untuk menjaga-jaga bila `SkillMeta.estimatedMinutes` suatu saat diisi 0 atau negatif oleh penulis konten — dicatat sebagai pengaman di T4, bukan perubahan desain besar.
10. **`quiz_questions.correct_answer` tetap bisa dibaca klien** (tidak ada column-level security, dan RLS `SELECT` berbasis `is_published` saja) — migrasi sendiri sudah berkomentar "do not expose correct_answer to student clients in production". Ini **mengkonfirmasi**, bukan mengoreksi, keputusan desain #13 (dicatat sebagai batasan, perbaikan pasca-MVP di T17). Tidak ada tindakan baru di plan ini.

Tidak ada kolom `NOT NULL` lain yang terlewat: `categories.name/slug`, `topics.name/slug/subject/difficulty_level/source_type/order_sequence`, `materials.title/material_type/difficulty_level/estimated_minutes`, `quiz_questions.question/question_type/skill_key/difficulty_level` seluruhnya punya nilai dari generator (langsung dari konten atau dari `mappings.mjs`); `topics.category_id`, `materials.topic_id`, `quiz_questions.material_id/step_id`, `*.created_by` nullable dan ditangani (SET NULL by FK atau diisi via subquery slug).

## Keputusan desain (dengan alasan, sudah termasuk koreksi di atas)

1. Sumber kebenaran = repo JSON (ditinjau lewat git, diverifikasi Python). DB = salinan untuk FK `quiz_attempts`, statistik, dan pemakaian tim. Jangan menyunting konten langsung di DB.
2. Satu baris `materials` per skill: `topic_id` = topik, `title` = nama skill, `description` = `goal`, `content` = `JSON.stringify(material)` disimpan sebagai string biasa ke kolom `TEXT` (bukan `::jsonb`, lihat koreksi #5), `material_type = 'article'`, `difficulty_level` = level topik terpetakan, `estimated_minutes` dari field opsional baru `SkillMeta.estimatedMinutes` (default 8, diklem minimal 1 — koreksi #9), `is_published = true` **ditulis eksplisit** (koreksi #4). Soal skill itu menunjuk `material_id` baris ini → soal terhubung ke topik lewat `materials.topic_id`, tanpa ubah skema.
3. `quiz_questions`: `question` = `prompt` + (`code` ? `"\n\n```python\n" + code + "\n```"` : `""`); `question_type = 'multiple_choice'` untuk semua tipe kita (tipe pedagogis asli `predict_output`/`predict_error`/`choose_code` tetap hanya di JSON, **tidak ada kolom DB untuk ini** — lihat koreksi #3 dan catatan terbuka #4); `options` = array `{id, text, misconception?, feedback?}` langsung dari `QuestionOption[]`; `correct_answer = {"optionId": q.correctOptionId}`; `explanation`; `skill_key` = `SkillContent.skillKey`; `difficulty` `easy→beginner`, `medium→intermediate`, `hard→advanced`; `step_id = null` (selalu, memenuhi `CHECK` — koreksi #6); `is_published = true` ditulis eksplisit untuk soal aktif.
4. Peta enum di satu tempat (`scripts/seed/mappings.mjs`): `LEVEL_MAP` (`pemula/menengah/lanjut → beginner/intermediate/advanced`), `DIFFICULTY_MAP` (`easy/medium/hard → beginner/intermediate/advanced`), `CATEGORY_SUBJECT` (slug kategori → nilai `topics.subject`, koreksi #1), konstanta `TOPIC_SOURCE_TYPE = 'admin'` (koreksi #3), `clampMinutes(n)` (koreksi #9).
5. ID: `categories`/`topics` memakai `IDENTITY bigint` → di SQL dirujuk lewat `slug` (subquery `(select id from topics where slug = '...')`), upsert `on conflict (slug) do update ...`; constraint tambahan `UNIQUE (name, subject)` tidak dilanggar karena hanya satu topik per `(name, subject)` saat ini (diuji, koreksi #2). `materials` dan `quiz_questions` memakai UUID v5 deterministik dari namespace tetap + id konten (`material:<skillKey>`, `question:<questionId>`), dihitung dengan `node:crypto` SHA-1 (tanpa dependensi), upsert `on conflict (id) do update`. Akibatnya seed bisa dijalankan berulang dan id soal stabil sehingga riwayat `quiz_attempts` tidak putus (dikonfirmasi penting oleh `ON DELETE CASCADE`, koreksi #7).
6. Penghapusan: soal/materi yang ada di DB dengan id hasil seed tetapi tidak lagi ada di JSON di-set `is_published = false`, tidak di-DELETE. Generator menulis daftar id aktif; SQL melakukan `update ... set is_published = false where id not in (...) and material_id in (materi seed topik ini)`.
7. Katalog: kategori "Pemrograman" (`is_published = true`, eksplisit). Topik selain Dasar Pemrograman TIDAK di-seed sampai lengkap ("sedikit tapi dalam"); `catalog.ts` landing tetap statis. Topik hanya `is_published = true` bila semua skill di unit demo (Unit 1-3) punya file dan lulus verifikasi; generator menolak publish topik yang belum lengkap (flag `--allow-incomplete` hanya untuk dev, menghasilkan `topics.is_published = false` eksplisit, bukan mengandalkan default — koreksi #4).
8. Escaping SQL: string literal dengan `''` untuk kutip tunggal (`standard_conforming_strings on`), JSON lewat `'...'::jsonb` **hanya untuk kolom JSONB asli** (`options`, `correct_answer`) — **bukan** `materials.content` yang `TEXT` biasa (koreksi #5). Tidak ada interpolasi mentah; satu fungsi `sqlString(s)` yang dites dengan kutip, backslash, baris baru, dan blok ```` ``` ````.
9. Satu transaksi: seluruh seed dalam `begin; ... commit;` agar gagal = tidak ada yang berubah.
10. Lokasi: `supabase/seed.sql` (dijalankan otomatis oleh `supabase db reset` lokal — proses ini berjalan sebagai `postgres`, melewati RLS). Untuk proyek hosted: dijalankan manual lewat SQL editor atau `psql` oleh anggota tim yang memegang kredensial admin/`service_role`, karena **tidak ada policy INSERT/UPDATE apa pun** untuk `categories`/`topics`/`materials`/`quiz_questions` (koreksi #8) — peran `anon`/`authenticated` tidak akan pernah bisa menjalankan seed ini, jadi ini bukan sekadar "butuh izin", tapi butuh koneksi yang secara teknis bisa bypass RLS. Agent tidak menjalankan seed ke DB bersama tanpa izin eksplisit user.
11. Kontrak dengan migrasi: tes membaca file migrasi, mengekstrak nilai `CHECK ... IN (...)` **per kolom per tabel** (bukan regex global, karena `difficulty_level` muncul identik di tiga tabel tapi `source_type` hanya di `topics` — koreksi #2/#3) dan memastikan semua nilai yang dihasilkan generator termasuk di dalamnya → bila tim mengubah enum, tes gagal lebih dulu.
12. Volume bank soal: naikkan ke 10 soal per skill untuk Unit 1-3 (diagnostic maks 4 + latihan sampai yakin + checkpoint 1-2; 8-9 terlalu tipis karena soal tidak diulang). Komposisi per skill: ≥2 easy, ≥4 medium, ≥2 hard; ≥1 `predict_error` bila skill punya error khas; ≥1 `choose_code`. Validator (`src/content/validateContent.ts`) diperbarui. **Status sekarang: hanya `variabel.json` punya 9 soal; 16 skill lain belum ditulis** (lihat "Status saat ini").
13. Diluar seed (gated, butuh persetujuan tim): migrasi `supabase/migrations/<ts>_student_mastery_write_own.sql` berisi policy insert/update own (SQL sama dengan yang sudah disetujui user untuk dibawa ke tim) — perlu karena `student_mastery` di migrasi sekarang hanya punya policy `SELECT`, tidak ada `INSERT`/`UPDATE`, sehingga BKT client-side tidak bisa menulis mastery sama sekali tanpa migrasi ini. Dicatat juga sebagai batasan: `correct_answer` terbaca klien (pengecekan jawaban di server = pasca-MVP, koreksi #10).

## Global Constraints

- Tanpa dependensi baru.
- Konten JSON (`src/content/**`) tidak diedit oleh generator — generator hanya membaca.
- Tidak mengubah tabel/kolom tim di `20261013035717_fullSql.sql`.
- Tidak menjalankan seed ke DB hosted tanpa izin eksplisit user (koreksi #8: ini juga secara teknis tidak mungkin lewat `anon`/`authenticated`).
- Semua perubahan RLS (T14) butuh persetujuan tim sebelum dibuat sebagai migrasi terpisah, dan tidak dieksekusi oleh agent ke DB bersama.
- Tidak commit kecuali diminta user.
- Konten soal (materi, bank soal) ditulis/disunting model utama; subagent murah hanya draf konten dan tugas mekanis pipeline (uuid, sql escaping, mappings, build/render, tes, menjalankan `npm run test`/`npm run content:verify`).
- Setiap skill wajib lulus `npm run test` (termasuk `validateContent.test.ts`) dan `npm run content:verify` sebelum masuk seed.
- `vite.config.ts` tidak disentuh (lihat "Status saat ini" — Vitest default sudah menyertakan `*.test.mjs`).

## Review Focus (paling mungkin gagal lebih dulu)

1. UUID v5 benar (bit versi 5 / variant RFC 4122) dan stabil antar-run — vektor uji resmi harus lulus persis.
2. Escaping SQL pada konten berkode: kutip tunggal, backslash, baris baru, dan blok ```` ``` ```` di dalam `materials.content`/`quiz_questions.question`.
3. Soal yang dihapus dari JSON tidak pernah memicu `DELETE` → tidak men-cascade hapus `quiz_attempts` (koreksi #7 mengonfirmasi risiko ini nyata, bukan teoretis).
4. Nilai enum lolos semua `CHECK`, termasuk yang berbeda per kolom (`topics.source_type = 'admin'` bukan `'manual'`, koreksi #3) dan `is_published` selalu ditulis eksplisit (koreksi #4), bukan default tabel.
5. Urutan `INSERT` memenuhi FK dan constraint unik ganda (`topics.slug` dan `topics (name, subject)`, koreksi #2).
6. Seed idempoten: dijalankan 2× menghasilkan jumlah baris dan isi yang identik (upsert, bukan insert buta).
7. Topik tidak ikut terbit (`is_published = true`) bila ada skill Unit 1-3 yang belum punya file atau belum lulus verifikasi.

## Fase & Tasks

### Fase A — Pipeline seed (mekanis, subagent murah boleh, bisa dikerjakan sekarang)

#### T1 — `uuidV5` + tes
- **Files:** `scripts/seed/uuid.mjs`, `scripts/seed/uuid.test.mjs`
- **Interfaces:** `uuidV5(namespace: string, name: string): string`
- Langkah:
  - [ ] Implementasikan UUID v5 (SHA-1 dari `namespace bytes + name bytes`, set bit versi `0101` di byte 6, set bit variant `10` di byte 8).
  - [ ] Tes vektor resmi: namespace DNS (`6ba7b810-9dad-11d1-80b4-00c04fd430c8`) + `"www.example.com"` → `2ed6657d-e927-568b-95e1-2665a8aea6a2`.
  - [ ] Tes stabilitas: dua pemanggilan dengan input sama → output sama.
  - [ ] Tes namespace tetap proyek (konstanta baru, mis. UUID v4 acak dibekukan sekali sebagai `SEED_NAMESPACE`) menghasilkan ID berbeda dari namespace DNS untuk input yang sama.
- **Verify:** `npm run test -- uuid`
- **Who:** subagent murah

#### T2 — `sqlString`/`sqlJson` + tes escaping
- **Files:** `scripts/seed/sql.mjs`, `scripts/seed/sql.test.mjs`
- **Interfaces:** `sqlString(s: string): string` (mengembalikan literal `'...'` siap tempel), `sqlJson(value: unknown): string` (mengembalikan `'...'::jsonb`)
- Langkah:
  - [ ] `sqlString`: ganti `'` → `''`; **tidak** melakukan escape backslash (standard_conforming_strings default ON di Postgres modern, jadi backslash literal, bukan escape char) — tes eksplisit memverifikasi ini.
  - [ ] Tes dengan kutip tunggal, backslash mentah, baris baru, dan blok ```` ``` ```` (konten materi/soal berkode).
  - [ ] `sqlJson`: `JSON.stringify` lalu lewat `sqlString`, ditutup `::jsonb`. **Catatan koreksi #5:** `sqlJson` TIDAK dipakai untuk `materials.content` (kolom `TEXT`) — hanya untuk `options`/`correct_answer`/`learning_objectives`-style JSONB. Tambah tes negatif yang menegaskan `renderSql.mjs` memakai `sqlString` biasa untuk `materials.content`.
- **Verify:** `npm run test -- sql`
- **Who:** subagent murah

#### T3 — `mappings.mjs` + tes kontrak terhadap migrasi
- **Files:** `scripts/seed/mappings.mjs`, `scripts/seed/mappings.test.mjs`
- **Interfaces:** `LEVEL_MAP`, `DIFFICULTY_MAP`, `CATEGORY_SUBJECT`, `TOPIC_SOURCE_TYPE`, `clampMinutes(n: number): number`
- Langkah:
  - [ ] `LEVEL_MAP = { pemula: "beginner", menengah: "intermediate", lanjut: "advanced" }`.
  - [ ] `DIFFICULTY_MAP = { easy: "beginner", medium: "intermediate", hard: "advanced" }`.
  - [ ] `CATEGORY_SUBJECT = { pemrograman: "Pemrograman" }` (koreksi #1 — dicatat sebagai asumsi, lihat "Terbuka" #5).
  - [ ] `TOPIC_SOURCE_TYPE = "admin"` (koreksi #3).
  - [ ] `clampMinutes(n) => Math.max(1, Math.round(n ?? 8))` (koreksi #9).
  - [ ] Tes kontrak: baca `supabase/migrations/20261013035717_fullSql.sql` sebagai teks, untuk tiap `(tabel, kolom)` yang relevan (`topics.difficulty_level`, `topics.source_type`, `materials.material_type`, `materials.difficulty_level`, `quiz_questions.question_type`, `quiz_questions.difficulty_level`) ekstrak isi `CHECK (<kolom> IN (...))` **persis di bawah definisi kolom tersebut** (regex per blok `CREATE TABLE ... <kolom> ... CHECK (...)`, bukan regex global satu kali — koreksi #2/#3 membuktikan dua tabel bisa punya kolom bernama sama dengan enum sama tapi tabel lain punya kolom enum lain), lalu assert semua nilai target (`"beginner"`, `"intermediate"`, `"advanced"`, `"admin"`, `"article"`, `"multiple_choice"`) ada di dalamnya.
- **Verify:** `npm run test -- mappings`
- **Who:** subagent murah, model utama meninjau regex kontrak (bagian paling mudah salah)

#### T4 — `buildRows(topic, skillFiles, opts)`

## Perkiraan volume

Unit 1-3: 10 skill × 10 soal = 100 soal + 10 materi. Unit 4-5: +70 soal + 7 materi. Total akhir topik Dasar Pemrograman: 1 kategori, 1 topik, 17 materi, 170 soal. **Saat ini (sebelum T9-T12): 1 materi, 9 soal** — pipeline (Fase A) diverifikasi dengan volume kecil ini lebih dulu.

## Risiko

- Skema tim berubah lagi → mitigasi: tes kontrak T3 gagal lebih dulu, sebelum data salah ter-generate.
- Topik hosted ditimpa manual di DB oleh anggota tim lain → mitigasi: aturan "sumber kebenaran = repo", `seed.sql` di-commit agar diff terlihat.
- `scripts/verify-content.mjs` belum mendukung `input()`/`stdin` → relevan untuk skill `input-konversi` (T10), ditangani di plan konten (`2026-10-15-content-dasar-pemrograman.md` T10), bukan di plan ini.
- Kualitas konten → spot-check tim per skill sebelum `file` diisi di `topic.json`.
- Docker tidak tersedia di mesin dev → T7 jadi "catat sebagai blocker, uji manual di staging" tanpa menghentikan Fase B.
- Asumsi `topics.subject = "Pemrograman"` (koreksi #1) belum dikonfirmasi tim — bisa perlu diubah bila tim punya konvensi `subject` yang berbeda.

## Terbuka (keputusan user/tim)

1. Persetujuan policy `student_mastery` (T14).
2. Siapa menjalankan seed di hosted (T15) — perlu kredensial admin/`service_role`, bukan `anon`.
3. Frontend membaca soal dari DB (ID deterministik sama, direkomendasikan karena konsisten dengan seluruh desain ID v5) atau dari JSON bundel langsung — diputuskan di plan halaman diagnostic, bukan di sini.
4. Apakah topik "segera hadir" (belum lengkap) juga ikut di-seed dengan `is_published = false` supaya tim admin bisa melihatnya di DB, atau sama sekali tidak disentuh sampai lengkap.
5. **Baru:** nilai `topics.subject` ("Pemrograman") hanya asumsi generator (koreksi #1) — belum ada field sumber di `TopicContent` maupun konfirmasi tim soal makna kolom ini.
6. **Baru:** tipe pedagogis asli soal (`predict_output`/`predict_error`/`choose_code`) tidak punya rumah di skema DB saat ini (koreksi #3) — bila nanti dibutuhkan untuk analitik atau AI Tutor, perlu kolom baru atau disisipkan ke `explanation`/metadata lain; tidak diputuskan di plan ini.
